# ESPDeck

**ESPDeck** — портативное многофункциональное устройство на базе микроконтроллера ESP32 с TFT-дисплеем, предназначенное для отображения погодной информации и данных о воспроизводимой музыке со смартфона.

Проект выполнен в стилистике организации **NERV** из вселенной «Евангелион». Интерфейс устройства использует характерное сочетание чёрного, красного и белого цветов, минималистичные графические элементы и тематические обозначения разделов.

Прошивка написана на **C++** с использованием Arduino Framework. Для реализации беспроводной связи применяются Wi-Fi и Bluetooth Low Energy (BLE). Получение погодной информации осуществляется через Open-Meteo API, а сведения о воспроизводимой музыке передаются со смартфона iPhone посредством Apple Media Service (AMS).

## Возможности проекта

### Погодный экран

- Получение актуальной погодной информации через Open-Meteo API.
- Отображение температуры воздуха.
- Отображение ощущаемой температуры.
- Отображение относительной влажности воздуха.
- Отображение скорости ветра.
- Преобразование погодных кодов в текстовые описания на русском языке.
- Автоматическое обновление погодной информации.
- Отображение состояния подключения к Wi-Fi.

### Музыкальный экран

- Подключение к смартфону через Bluetooth Low Energy.
- Получение информации через Apple Media Service (AMS).
- Поддержка отображения информации из Яндекс Музыки на iPhone.
- Отображение названия музыкального приложения.
- Отображение названия композиции.
- Отображение имени исполнителя.
- Отображение названия альбома.
- Отображение состояния воспроизведения.
- Графический индикатор прогресса композиции.
- Отображение прошедшего и общего времени воспроизведения.
- Автоматическое обновление информации при переключении треков.
- Поддержка русскоязычных названий композиций и исполнителей.

### Беспроводная связь

- Подключение к домашней сети Wi-Fi.
- Подключение к резервной точке доступа смартфона.
- Автоматическое переключение между сетевыми профилями.
- Контроль состояния подключения.
- Повторные попытки подключения при потере связи.
- Bluetooth-соединение со смартфоном без передачи аудиопотока.

### Пользовательский интерфейс

- Вертикальная ориентация дисплея.
- Разрешение 240 × 320 пикселей.
- Стилистика NERV из Evangelion.
- Поддержка кириллицы.
- Автоматическое переключение между погодным и музыкальным экранами.
- Динамическое обновление музыкального прогресс-бара.

## Подключение дисплея

Дисплей подключается к ESP32 посредством последовательного интерфейса SPI.

Используемое распределение выводов:

| Вывод дисплея | Вывод ESP32 |
|---|---|
| TFT_CS | GPIO 27 |
| TFT_DC | GPIO 26 |
| TFT_RST | GPIO 25 |
| TFT_SCK | GPIO 18 |
| TFT_MISO | GPIO 19 |
| TFT_MOSI | GPIO 23 |

Настройка выводов выполняется в начале программы:

```cpp
#define TFT_CS    27
#define TFT_DC    26
#define TFT_RST   25

#define TFT_SCK   18
#define TFT_MISO  19
#define TFT_MOSI  23
```

Инициализация дисплея выполняется с использованием библиотеки Adafruit_ST7789:

```cpp
SPI.begin(TFT_SCK, TFT_MISO, TFT_MOSI, TFT_CS);

tft.init(240, 320);
tft.setRotation(0);
tft.invertDisplay(false);
```

## Настройка Wi-Fi

В проекте предусмотрено использование двух сетевых профилей: домашней сети и мобильной точки доступа смартфона.

Параметры подключения задаются в начале программы:

```cpp
const char* HOME_WIFI_SSID = "HOME_WIFI_SSID";
const char* HOME_WIFI_PASSWORD = "HOME_WIFI_PASSWORD";

const char* PHONE_WIFI_SSID = "PHONE_WIFI_SSID";
const char* PHONE_WIFI_PASSWORD = "PHONE_WIFI_PASSWORD";
```

Необходимо заменить значения на реальные параметры используемых сетей.

### Алгоритм подключения

1. ESP32 проверяет наличие настроенных сетевых профилей.
2. Первоначально выполняется попытка подключения к домашней сети.
3. Если подключение не удалось за установленное время, выбирается мобильная точка доступа.
4. При потере установленного соединения выполняется переключение на альтернативный профиль.
5. При успешном подключении запускается получение погодной информации.

Время ожидания подключения составляет 15 секунд. Интервал между повторными попытками составляет 1,5 секунды.

Для корректной работы мобильной сети необходимо предварительно включить точку доступа на смартфоне.

## Настройка Bluetooth

Для получения информации о воспроизводимой музыке используется протокол Apple Media Service.

Bluetooth-модуль реализован посредством библиотеки NimBLE-Arduino.

После запуска ESP32 начинает рекламировать устройство под названием:

```text
ESPDeck
```

Для подключения необходимо:

1. Открыть настройки Bluetooth на iPhone.
2. Найти устройство ESPDeck.
3. Установить соединение.
4. Дождаться установления защищённого соединения.
5. Дождаться обнаружения сервиса Apple Media Service.

После успешной настройки ESP32 начинает получать информацию о музыкальном проигрывателе и текущей композиции.

### Получаемые данные

| Параметр | Описание |
|---|---|
| Player Name | Название музыкального приложения |
| Track Title | Название композиции |
| Artist | Исполнитель |
| Album | Альбом |
| Duration | Продолжительность композиции |
| Playback Info | Состояние воспроизведения и текущая позиция |

Передача аудиопотока через ESP32 не выполняется. Музыка продолжает воспроизводиться через выбранное на iPhone устройство вывода звука, например AirPods Pro.

ESPDeck получает только информацию о воспроизводимой композиции.

## Получение погодных данных

Для получения погодной информации используется сервис Open-Meteo.

Сервис предоставляет данные о погоде в формате JSON и не требует API-ключа для используемого запроса.

### Географические параметры

В текущей версии используются координаты города Омска:

```cpp
const float WEATHER_LATITUDE = 55.008785;
const float WEATHER_LONGITUDE = 73.3267;

const char* WEATHER_TIMEZONE = "Asia/Omsk";
```

### Получаемые параметры

- `temperature_2m` — температура воздуха;
- `apparent_temperature` — ощущаемая температура;
- `relative_humidity_2m` — относительная влажность;
- `weather_code` — погодный код;
- `wind_speed_10m` — скорость ветра.

### Особенности сетевого подключения

Из-за проблем с DNS-разрешением адреса Open-Meteo в используемой сетевой конфигурации применяется прямое подключение к IP-адресу сервера с сохранением имени хоста для TLS SNI.

В программе предусмотрены два IP-адреса для попыток подключения.

После установления TLS-соединения HTTP-запрос отправляется непосредственно через открытый сетевой сокет. Это позволяет избежать повторного DNS-разрешения при выполнении запроса.

Ответ сервера обрабатывается вручную с поддержкой `Content-Length` и `chunked` передачи.

Полученные данные преобразуются библиотекой ArduinoJson и сохраняются в переменных программы.

### Периодичность обновления

| Событие | Интервал |
|---|---|
| Успешное обновление погоды | 10 минут |
| Повторная попытка после ошибки | 1 минута |
| Повторное подключение Wi-Fi после потери связи | 1,5 секунды после переключения профиля |

## Архитектура прошивки

Прошивка построена по модульному принципу. Основные задачи разделены на несколько функциональных блоков, взаимодействующих через общий цикл программы и очередь сообщений FreeRTOS.

### Общая схема работы

```text
                 ESP32
                   |
        +----------+----------+
        |                     |
     TFT-дисплей          Беспроводная связь
        |                     |
   +----+----+           +----+----+
   |         |           |         |
Погода    Музыка        Wi-Fi     BLE
   |         |           |         |
   |         |       Open-Meteo   iPhone
   |         |                     |
   |         |               Apple Media
   |         |                 Service
   |         |                     |
   |         +---------------------+
   |
 Автоматическое переключение
       двух экранов
```

### Основные программные блоки

**1. Графический интерфейс**

Отвечает за создание экранов, отображение текстовой информации, графических элементов и прогресс-бара воспроизведения.

**2. Wi-Fi и получение погоды**

Отвечает за подключение к беспроводным сетям, переключение между профилями, получение погодных данных и их обработку.

**3. Bluetooth и AMS**

Обеспечивает соединение с iPhone, получение музыкальных уведомлений и извлечение информации о текущей композиции.

**4. Обработка сообщений FreeRTOS**

Использует очередь для передачи Bluetooth-уведомлений из обработчика событий в основной цикл программы.

**5. Управление экранами**

Определяет, какой экран необходимо отображать в зависимости от состояния воспроизведения музыки.

## Описание основных функций

### Инициализация и главный цикл

`void setup()` — выполняет первоначальную настройку устройства. Запускает последовательное соединение, создаёт очередь FreeRTOS, инициализирует SPI и TFT-дисплей, настраивает шрифты, запускает Wi-Fi и Bluetooth, после чего отображает главный погодный экран.

`void loop()` — основной цикл работы прошивки. Последовательно выполняет обработку Bluetooth-соединения, получение музыкальных сообщений, контроль Wi-Fi, обновление погоды и управление отображением экранов.

### Работа с музыкальной информацией

`void startBLE()` — запускает Bluetooth Low Energy, создаёт сервер NimBLE, устанавливает параметры безопасности, формирует рекламные пакеты и делает устройство ESPDeck доступным для подключения смартфона.

`void serviceAMSConnection()` — отвечает за установление защищённого Bluetooth-соединения, поиск сервиса Apple Media Service, обнаружение характеристик и подписку на уведомления.

`void onAMSNotification()` — обработчик входящих уведомлений AMS. Получает данные о музыкальном проигрывателе и композиции, после чего помещает их в очередь FreeRTOS.

`void processAMSMessage()` — обрабатывает полученные сообщения. Определяет тип информации и обновляет название приложения, композицию, исполнителя, альбом, продолжительность и состояние воспроизведения.

`void serviceAMSQueue()` — извлекает накопленные сообщения из очереди FreeRTOS и передаёт их на обработку.

`float currentTrackElapsed()` — рассчитывает текущее время воспроизведения с учётом последней полученной позиции, скорости воспроизведения и прошедшего времени.

`void resetProgressForNewTrack()` — сбрасывает параметры прогресса при обнаружении новой композиции. Предотвращает сохранение позиции предыдущего трека при автоматическом переключении музыки.

`bool musicShouldBeVisible()` — определяет необходимость отображения музыкального экрана. Учитывает состояние Bluetooth-соединения, воспроизведения и время после последнего музыкального обновления.

`String formatTimeSeconds()` — преобразует время воспроизведения из секунд в формат минут и секунд.

### Работа с Wi-Fi

`bool profileHasCredentials()` — проверяет наличие настроенных параметров выбранной беспроводной сети.

`void startWiFiAttempt()` — выбирает доступный сетевой профиль и запускает подключение к домашней сети или мобильной точке доступа.

`void serviceWiFi()` — контролирует состояние Wi-Fi. При потере соединения переключает сетевой профиль и инициирует повторное подключение. После успешного подключения настраивает часовой пояс и системное время.

### Получение погодной информации

`bool fetchWeather()` — выполняет запрос к Open-Meteo. Устанавливает TLS-соединение с сервером по заданному IP-адресу, отправляет HTTP GET-запрос, получает JSON-ответ и извлекает необходимые погодные параметры.

`bool readWeatherBytes()` — считывает заданное количество байтов из установленного TLS-соединения с контролем времени ожидания.

`bool readWeatherBody()` — обрабатывает тело HTTP-ответа. Поддерживает получение данных с использованием Content-Length и chunked encoding.

`void serviceWeather()` — контролирует периодичность обновления погодной информации. При успешном запросе устанавливает интервал обновления 10 минут, при ошибке выполняет повторную попытку через минуту.

`String weatherCodeToRussian()` — преобразует погодные коды Open-Meteo в текстовые описания на русском языке.

### Отображение информации

`void drawWrappedUTF8()` — выполняет вывод текстовой информации с поддержкой UTF-8. Реализует перенос строк с учётом ширины доступной области дисплея.

`void drawHeader()` — формирует верхнюю часть интерфейса. Отображает название NERV, заголовок текущего экрана и разделительную линию.

`void drawProgressBar()` — отображает графический индикатор воспроизведения. Рассчитывает положение текущей позиции относительно общей продолжительности композиции и выводит временные значения.

`void drawWeatherScreen()` — формирует погодный экран. Отображает температуру, ощущаемую температуру, погодные условия, влажность, скорость ветра и состояние Wi-Fi.

`void drawMusicScreen()` — формирует музыкальный экран. Отображает музыкальное приложение, название композиции, исполнителя, альбом, состояние воспроизведения и прогресс-бар.

`void serviceDisplay()` — управляет переключением между погодным и музыкальным экранами. При обнаружении воспроизведения автоматически открывает музыкальный экран, а после остановки музыки и истечения установленного времени возвращает погодный экран.

### Обработка Bluetooth-событий

`ESPDeckServerCallbacks` — класс обратных вызовов BLE-сервера. Обрабатывает подключение и отключение iPhone, обновляет состояние соединения и сбрасывает параметры обнаружения AMS при необходимости.

Код программы приведён в файле `ESPDeck_compact.ino`.

## Логика работы интерфейса

В текущей версии реализованы два основных экрана.

### Главный экран — SYSTEM // WEATHER

Предназначен для отображения погодной информации.

Содержит:

- название города;
- температуру воздуха;
- ощущаемую температуру;
- описание погодных условий;
- относительную влажность;
- скорость ветра;
- состояние Wi-Fi-соединения.

### Музыкальный экран

Предназначен для отображения информации о композиции, воспроизводимой на смартфоне.

Содержит:

- название музыкального приложения;
- название композиции;
- исполнителя;
- альбом;
- состояние воспроизведения;
- графический прогресс-бар;
- текущее и общее время композиции.

### Автоматическое переключение

Переключение между экранами происходит без использования физических кнопок.

Алгоритм работы:

1. При включении устройства отображается погодный экран.
2. При подключении iPhone устанавливается соединение с Apple Media Service.
3. При начале воспроизведения музыки выполняется переход на музыкальный экран.
4. При переключении композиции обновляются название, исполнитель, альбом и продолжительность.
5. Прогресс-бар обновляется с интервалом 250 мс.
6. При остановке воспроизведения музыкальный экран сохраняется до 90 секунд после последнего обновления.
7. После истечения этого времени устройство возвращается к погодному экрану.

## Типовые сценарии использования

### Получение погоды

1. Пользователь включает ESPDeck.
2. Микроконтроллер запускает Wi-Fi.
3. Выполняется подключение к настроенной беспроводной сети.
4. После подключения запускается запрос к Open-Meteo.
5. Полученные данные обрабатываются через ArduinoJson.
6. Погодная информация отображается на TFT-дисплее.
7. Через 10 минут выполняется очередное обновление.

### Отображение музыкальной композиции

1. Пользователь включает Bluetooth на iPhone.
2. Подключается к устройству ESPDeck.
3. ESP32 устанавливает защищённое соединение.
4. Выполняется обнаружение Apple Media Service.
5. Микроконтроллер подписывается на музыкальные уведомления.
6. При запуске Яндекс Музыки получает информацию о воспроизводимой композиции.
7. Название трека, исполнитель и альбом отображаются на дисплее.
8. При смене композиции информация обновляется автоматически.

### Работа без домашнего Wi-Fi

1. Пользователь включает мобильную точку доступа на смартфоне.
2. ESPDeck обнаруживает отсутствие домашнего подключения.
3. Выполняет попытку подключения к резервному сетевому профилю.
4. После подключения получает погодную информацию через интернет смартфона.

## Ограничения текущей версии

В текущей версии прошивки реализованы погодный и музыкальный экраны.

На данный момент:

- мониторинг характеристик компьютера не реализован;
- отображение обложек музыкальных композиций не реализовано;
- управление музыкой непосредственно с ESPDeck не реализовано;
- запись информации на SD-карту не используется;
- физическая кнопка переключения экранов отсутствует;
- получение музыкальной информации реализовано через Apple Media Service для iPhone.

Для получения погодных данных требуется подключение к интернету.

В текущей реализации TLS-соединение устанавливается с отключённой проверкой сертификата сервера (`setInsecure()`). Это техническое ограничение используемой версии прошивки.

## Troubleshooting

### ESP32 не подключается к Wi-Fi

Проверьте правильность значений:

```cpp
HOME_WIFI_SSID
HOME_WIFI_PASSWORD

PHONE_WIFI_SSID
PHONE_WIFI_PASSWORD
```

Убедитесь, что соответствующая сеть доступна, а точка доступа смартфона включена.

### Не отображается погода

Проверьте:

- наличие интернет-соединения;
- правильность координат;
- состояние Wi-Fi;
- доступность сервера Open-Meteo.

В прошивке используются прямые IP-адреса сервера. При изменении сетевой инфраструктуры сервиса может потребоваться обновление адресов.

Успешное получение погодных данных подтверждается сообщением:

```text
[WEATHER] TLS CONNECTED.
[WEATHER] HTTP request sent through pinned TLS socket.
[WEATHER] Status line: HTTP/1.1 200 OK
[WEATHER] JSON bytes received: ...
```

### Не отображается информация о музыке

Проверьте:

- включён ли Bluetooth на iPhone;
- установлено ли соединение с ESPDeck;
- доступен ли сервис Apple Media Service;
- запущено ли музыкальное приложение.

После подключения может потребоваться некоторое время для установления защищённого соединения и обнаружения характеристик AMS.

### Некорректно отображается кириллица

Проверьте наличие библиотеки:

```text
U8g2_for_Adafruit_GFX
```

Также необходимо убедиться, что используются шрифты с поддержкой кириллицы.

### Не работает прогресс-бар

Проверьте получение уведомлений Playback Info и Duration от Apple Media Service. Для корректного отображения должны поступать текущая позиция воспроизведения и продолжительность композиции.

## Дальнейшее развитие проекта

В дальнейшем планируется расширение функциональности ESPDeck.

Основным следующим этапом является разработка третьего раздела интерфейса **YOU CAN (NOT) SEE**, предназначенного для отображения характеристик и текущего состояния компьютера.

Предполагаемые направления развития:

- получение статистики компьютера;
- отображение загрузки процессора;
- отображение использования оперативной памяти;
- отображение температуры компонентов при наличии соответствующих датчиков;
- расширение графического интерфейса;
- развитие системы переключения разделов.

Проект продолжает развиваться с сохранением общей стилистики NERV и принципа компактного отображения информации на небольшом TFT-дисплее.
